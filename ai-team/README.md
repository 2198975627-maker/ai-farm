# Gao 的 AI 上下级协作系统 — 设计文档 v1

> 一句话：你只发任务，我（Muse）当总管，付费强模型当经理，免费模型当员工。
> 经理动脑、员工动手，总管负责拆单、派单、质检、整合。

最后更新：2026-11-16
状态：v1 手动版已可用，半自动脚本已搭好骨架，等你确认库存后启用。

---

## 1. 先说实话：哪些是真整合，哪些是假整合

不是所有 AI 都能真正“接进来”。分三种，别混了：

| 通道 | 能真整合的 | 办法 | 限制 |
|---|---|---|---|
| **API 直连（真整合）** | DeepSeek V4 Pro / V3、K-EXAONE 2.5、Qwen、GLM | 都是 OpenAI 兼容接口，一个 Python 脚本就能并行调用 | 要 Key、要按量付费或免费额度，K-EXAONE 12-10 到期，GLM 已用完 |
| **浏览器代管（半整合）** | Gemini 网页版、ChatGPT 网页版、Grok 网页版 | 由 Muse 用浏览器打开网页、发指令、等回复、取回结果，就像 11-16 白天对 Gemini 那样 | 慢、会卡、一次只能做一件事，不能 10 个并行。Gemini 今天就卡了 3 次 |
| **App 手动（目前接不进来）** | Grok App（GBox 里打不开）、手机 App、Workbuddy（是什么还没确认） | 只能你手动复制粘贴 | 别指望自动，等 GBox 修好或确认 Workbuddy 有没有 API / 网页版再说 |

**结论：**
- 后台批量工厂 = API 模型，用派单脚本跑。
- 大脑会诊 = 网页模型，用浏览器一个一个问。
- 共享记忆 = GitHub + 工单文件夹。模型之间不直接对话，都通过工单文件对话。
- 本地中枢 = 你电脑上的 DeepSeek Harness。它一次只能用一个模型，适合你个人工作台，不适合并行派单。

## 3. 分工原则：经理动脑，员工动手

| 活 | 谁做 | 为什么 |
|---|---|---|
| 听懂任务、拆成小任务、定验收标准 | 总管 Muse | 只有我记得你全部上下文 |
| 选技术方案、定架构、审关键代码 | 经理层 | 需要判断力，错了代价大 |
| 写大块新代码、改前端、写报告正文 | 经理层（Gemini / DeepSeek V4 Pro / GPT） | 需要连贯性和质量 |
| 批量翻译、批量生成初稿、写测试、格式化、分类、摘要、跑重复检查 | 员工层 | 明确、重复、错了也好改 |
| 最后合并、去重、统一风格、跑测试验证 | 总管 Muse | 防止各说各话 |
| 拍板、填密钥、点提交、付钱 | Gao | 只有你能做 |

**一条红线：员工不许做决定。**
员工拿到的指令必须是：目标 + 输入 + 输出格式 + 验收标准 + “不许自由发挥”。
员工输出经理只审 diff / 摘要，不重读全文。

## 4. 省 Token / 省算力的 5 条规则

这是这个系统存在的意义，不遵守就白搭了：

1. **小任务不请经理。** 能用员工做的，绝不叫 Argon / GPT-5。上次 Gemini 生成 Canvas 卡住，就是大任务 + 长输出的代价。
2. **经理不看全文，只看 diff。** 员工改了 5 个文件，经理只看改了哪几行 + 测试结果，不重读 500 行代码。
3. **指令模板化。** 每个工单固定格式（见 task-template.md），不许写散文式长指令。
4. **批量一次发。** 10 个翻译任务合成 1 次调用，10 个测试合成 1 个文件，别一次一次发。
5. **失败先降级，不升级。** 员工做砸了，先换另一个员工重试；两次都砸才升级给经理。反过来就烧钱。

## 5. 任务流转：7 步

```
1. Gao 发任务（一句话 + 目标）
   ↓
2. Muse 拆单 → 每个工单 = 1 个明确产出，写进 tasks/ 文件夹
   ↓
3. 经理定方案（选谁做、怎么验、预算多少 token）
   ↓
4. 员工并行执行（API 的用脚本并行，网页的我一个一个跑）
   ↓
5. 经理抽查质检（只看关键点 + 跑测试）
   ↓
6. Muse 整合（合并、去重、统一风格）
   ↓
7. Gao 验收（只看结果清单 + 要你做的 2-3 件事）
```

**通讯方式：**
- 模型之间不直接聊天。
- 唯一共享区 = `workspace/ai-team/tasks/` 里的工单文件 + GitHub。
- 一个工单从 `inbox/` → `doing/` → `review/` → `done/`，状态写在文件头。
- 总管每天 / 每个任务结束出一份进度清单，你不用去每个模型里翻。

## 6. 举个例子：足球项目收尾怎么走这套系统

任务：“把 DeepSeek 接入补齐，线上跑通一次真实 Live 预测”

- **总管 Muse：** 拆成 5 个工单：① DeepSeek 分支代码 ② 价格配置 ③ 测试 ④ Vercel 变量清单 ⑤ 线上验证步骤
- **经理 DeepSeek V4 Pro：** 写 ① 的实现方案，定接口走 Chat Completions（不是 Responses API）
- **经理 Gemini Argon：** 写 ⑤ 的验证文档 + 前端检查清单
- **员工 K-EXAONE：** 批量写 ③ 的测试用例初稿、批量翻译提示词
- **员工 Qwen Turbo：** 把 5 个工单的输出统一格式化成 Markdown
- **总管 Muse：** 合并代码、本地跑 40 个测试 + 构建、核对价格 880/29/2641、给你一份“只剩 2 件事等你”的清单
- **Gao：** 只做：选合入方式 + 去 Vercel 填密钥

这就是 11-16 白天我们实际走的流程，只是当时没写成制度。现在把它固定下来。

## 7. 落地三步走

### Phase 1 — 本周：手动版（不用写代码，今晚就能跑）
- 你发任务，我拆单，我用浏览器调 Gemini / GPT 网页，用 Harness / Codex 调 DeepSeek / K-EXAONE。
- 工单都存在 `tasks/` 里，你随时能看进度。
- 先跑足球项目收尾 + 大赛排练包，这是最急的。

### Phase 2 — 下周：半自动版
- 启用 `dispatcher.py`：API 模型并行派单，自动读工单、调接口、写回结果。
- 跑在 Simular Box 或 Cloady EU1 上（它们 24 小时在线的比你电脑稳，InstaBox 2 小时就断别用）。
- 网页模型还是我手动跑，API 模型自动跑。

### Phase 3 — 以后：常驻版
- 派单脚本常驻 + 定时检查 + 哪吒监控看状态。
- 你发一句话，系统自动拆单、派单、晚上给你汇总。
- 前提是 Phase 1/2 跑顺了，库存也确认了，再上。

## 8. 成本与风险

- **最贵的是经理。** Gemini Pro 到 12-15 结束，之后 158 元/月超你预算，别自动续。GPT Plus 如果你有，同样要算月费。
- **免费额度会过期/限流。** K-EXAONE 12-10 到期、429 限流是常态，要有备用员工。
- **网页模型会卡。** Gemini 今天卡 3 次是正常现象，别把关键路径只押在一个网页模型上。
- **密钥安全。** 所有 Key 走环境变量，绝不写进工单、绝不发到群里。Vercel / Supabase 的操作还是你亲自点。

## 9. 参考：RuFlo（X @WY_mask 2026-05-09 帖子，Gao 2026-11-16 分享）

来源：无颜 @WY_mask 帖子，介绍 ruvnet/ruflo，一个“AI调度中心”。
帖子当时称 GitHub 热门榜第一、4万+收藏。后续核实：RuFlo 前身是 Claude Flow，MIT 开源，截至 2026-10-20 约 77,473 stars、9,121 forks，10 月版本 v3.58.1；另一来源称 81,759 stars。Star 数很高，但不等于开箱即用。

**跟你想的像在哪：**
- 一次召唤几十个 Agent：有的写代码、有的自动测试、有的安全审计、有的负责部署/DevOps
- 分层/网状/自适应拓扑：我们的三层（总管-经理-员工）对应它的分层拓扑，小任务也可以走网状并行
- 多供应商智能路由：Claude、GPT、Gemini、Cohere、Ollama 等，哪个合适用哪个
- 共享记忆：AgentDB 向量记忆 + RAG，解决“Agent 失忆”
- 能跟 Claude Code / Codex 联动

**值得借到我们系统里的 4 点：**
1. 拓扑别只定死分层：大任务走分层（经理拆、员工做），小批量任务走网状并行
2. 共享记忆要持久化：现在我们用 GitHub + 工单文件，以后可以加一个统一的记忆文件（每个任务的结论、踩过的坑），别让每个模型各记各的
3. 后台自动工种：审计、测试差距检查、优化，这类触发式小活可以交给员工自动跑，不用每次都等你发话
4. 插件/技能市场思路：把常用的工单模板（写测试、翻译、格式化）沉淀成固定技能，下次直接调用

**不能照抄的 3 个坑：**
- 它是给 Claude Code / Codex 的重型开发编排器，要装 npm、写配置、跑终端，对新手不友好；我们的手动版不用装任何东西，今晚就能跑
- 宣传跑在代码前面：独立评测指出它有夸大的提速数字、部分工具是空壳、 hooks 不干活，SkillsLLM 安全扫描也报过高危问题。Star 多不代表每个功能都真能用
- Token 烧得更快：100+ Agent 并行 = 100+ 份上下文，RuFlo 本身免费（MIT），但底下的 Claude / GPT 用量是另算的。你的预算是每月 20 美元左右，必须坚持“小任务不请经理、经理只看 diff”那 5 条，不然 RuFlo 式全开很快就超支
- 适用面窄：RuFlo 主攻写代码，你的任务还包括大赛报告、CET-4、翻译、查资料，这些它不擅长

**结论：** 思路借它，形态不抄它。我们的系统 = RuFlo 的分工思想 + 你的实际情况（预算、鸿蒙、GBox、免费额度）的轻量版。等足球项目 + 大赛忙完，如果你想在电脑上试 RuFlo 再单独试，别现在上。

## 10. 免费农场：一家一个，薅多家的（Gao 2026-11-16 修正）

Gao 的原话思路：不是同一家多开 100 个，是每家只开一个免费的——一个免费 GPT 网页端、一个免费千问、一个免费豆包，等等，薅很多很多家每天 / 每周的免费额度，每个免费模型只做自己能承受的东西。

这是对的，比 RuFlo 的 100 个同引擎 Agent 更适合你。RuFlo 是同一套 Claude Code 引擎复制 100 份，费用乘 100 倍；你这个是 10 家各出 1 份，费用还是 0，量是加起来的。

**怎么分才扛得住：**
- 每家 1 个，绝不一家多开：多开同一家很快触发限流 / 封号，一家一个才是合规薅羊毛
- 任务切小：每个员工一次只做一小块，比如 1 个文件、300 字、10 条翻译，别把整个项目丢给一个免费模型
- 按特长派：千问 / 豆包做中文，GPT 免费做英文 / 代码，Gemini Flash 做长上下文，Kimi 做长文总结，DeepSeek 免费做代码，K-EXAONE 做批量初稿
- 轮换制：今天千问用完了换豆包，明天千问恢复了再换回来，总管记一个额度表，谁今天还能用、谁要等明天
- 网页免费档不能像 API 那样脚本并行：网页端只能由 Muse 用浏览器一个一个跑，或者你手动复制粘贴；API 免费档才能用 dispatcher.py 并行

**免费农场候选（待核实你每家有没有号）：**
- ChatGPT 免费网页端、Gemini 免费档、DeepSeek 免费聊天、K-EXAONE 免费 API（到 12-10）、千问免费、豆包免费（简单问答不限次数，重活有限额）、Kimi 免费、GLM 免费（已用完，等新额度）
- 注意：豆包免费版官方不给固定数字，简单问答不限，重活（PPT、深度研究、AI 表格）只说“满足日常使用”，高峰会排队

**红线：** 一家一个号是合规的，别为绕限额去注册一堆小号，那样容易被封，牵连主号。

## 11. 参考：OpenMausBot（X @NFT_Chen 2026-11-07 帖子，Gao 2026-11-16 分享）

OpenMausBot（milind-soni/OpenMausBot，Apache-2.0，约 22,457 stars）是“开源版 Grok Bot”：聊天 App 里一支 AI 团队，每个 Bot 有独立个性、模型、电脑、应用，可互相委派、可孵化对等 Bot、可一键分享整个团队。

**像免费农场的地方：** 团队形态、Bot 之间委派、整个团队一键分享——这正是我们办公室网站想做的样子。

**不一样的关键：** 它不是免费农场。它跑在你已有的 Claude / Codex / Grok CLI 订阅上，壳免费、模型调用仍按量计费，帖子说“X 会员瞬间失去意义、完全免费”夸大了，评论区也有人当场指出这一点。它只支持 Claude / Codex / Grok，不支持千问 / 豆包 / Kimi 这些免费网页额度，还要装 Electron 桌面 App（Mac/Win），不是网页拖一拖就能用。

**结论：** 形态可以借，成本模式不能借。我们的农场是多家免费网页额度轮换，它的模式是付费 CLI 换壳。大赛忙完后如果想在 Windows 上试它再单独试，现在先用我们轻量版办公室。

## 12. 参考：Octo（Pachat 视频评论区置顶评论提到，Gao 2026-11-19 让查，2026-11-20 写入）

来源：明略科技（Mininglamp）2026-06-29/30 开源的 AI-native 团队协作平台，Apache 2.0，可私有化部署，仓库在 GitHub 的 Mininglamp-OSS 组织（`https://github.com/Mininglamp-OSS`，含 octo-web / octo-server / octo-ios / octo-cli / octo-android 等仓库）。形态是 Web App、移动端、浏览器插件、CLI 四端。Agent 以 Bot 的身份进频道（Channel）和子任务（Thread），能接 OpenClaw、Hermes、Codex、Claude Code、WorkBuddy 等主流工具。

Octo 的名字本身就是四个维度，O.C.T.O.，缺一不可：

- **O — Open（开放）：** 开源、可自己部署，不同来源的 Agent 都能以 Bot 身份接进来，有统一身份。
- **C — Context（上下文）：** 工作上下文要保护，公开知识随便共享，内部知识要标明是谁的，个人的判断习惯只属于自己。
- **T — Taste（品味）：** AI 越来越会想、会干，但人的品味（判断力、眼光、经验积累出来的直觉）复制不走，人要在中间做决定。
- **O — Orchestration（编排）：** 人、Agent、工具都通过同一个协作层协调，也就是下面六种模式。

**六种协作模式，本质是六种信息拓扑，对应到农场这样用：**

| Octo 模式 | 意思 | 农场对应 | 状态（2026-11-20） |
|---|---|---|---|
| Solo（单干） | 一个人/一个 Bot 独立完成 | 一个员工独立做一个小工单 | 已有雏形：1 张工单 = 1 个员工线程 |
| Roundtable（圆桌讨论） | 多个 Bot 一起讨论，互相补充 | 多个员工对同一方案各提意见，总管汇总 | 未做：农场现在是总管单向派单，没有员工之间讨论 |
| Critic（生成-验证） | 一个做、一个独立验 | 一个员工写、另一个员工/经理审，不通过就打回重做 | 已有：ai-farm 18c463a 的写—审—改闭环就是这个 |
| Pipeline（流水线） | 按顺序接力，前一步的输出是后一步的输入 | 经理拆任务 → 员工做 → 总管整合 → Gao 验收 | 已有雏形：就是 §5 的 7 步流程 |
| Split（分头干） | 把大任务拆成几块，并行做 | 10 条翻译分给 3 个员工同时做 | API 通道已有（dispatcher 并行），网页通道不行（一次只能一个） |
| Swarm（撒网竞选） | 多个 Bot 各做一份，挑最好的那个 | 两个免费员工各写一份初稿，总管挑好的交 Gao | 未做：现在是 1 个员工做 1 份，失败才换人，不并行比稿 |

**值得借到农场里的 3 点：**
1. **O（Open）我们已经在走：** 图标就是槽位、模型随便换、开源在 GitHub 上，继续保持任何厂商的模型都能插进来，别把农场写死成某几家。
2. **T（Taste）就是 Gao 的位置：** Gao 是董事长、最后拍板的人，经理只出方案、员工只干活，最后好不好由 Gao 尝一下再定，这个不能省，也不能让经理代拍板。
3. **O（Orchestration）的六种模式当派单模板：** 以后派单时先选模式再派人——要质量选 Critic，要速度选 Split，要创意选 Swarm，要稳选 Pipeline，别每次都只用一种“经理拆、员工做”。

**不用借的 1 点：**
- **C（Context）的企业级那套：** Octo 是给一个组织里很多人共享 Agent、沉淀知识用的，空间/分组/频道/子区四层结构、知识归属和复用都是为团队设计的。农场是 Gao 一个人用，上下文就是 GitHub 当收发室 + 工单文件，没必要搞那么重。等以后真有人跟 Gao 一起用农场时再补。

**结论：** Octo 是这几个参考里最完整的一个，群聊协作 + 六种模式可以直接当农场下一步的派单参考，特别是 Roundtable 和 Swarm 这两个农场还没有的模式。但它不解决农场最核心的问题——免费额度轮换省钱，那块还是我们自己的：多家免费轮换、谁累了换另一家、钱只花在经理层订阅上。

## 13. 参考：Pachat（情报马 2026-11-11 抖音视频，Gao 2026-11-19 分享，2026-11-20 全站核查后写入）

来源：Pachat 官网 `https://pachat.ai/`（Gao 2026-11-20 给出并验证过，之前“视频里没找到网址”只限于抖音视频描述、已加载的 10 条评论和采样画面，不等于没有官网）。创始人周岩，深圳做过 13 年跨境电商和 SaaS，2026 年开始做 Pachat，团队不到 10 人。定位：把多个 agent 拉进一个群聊，互相核对、吵清楚，最后人拍板。注册是邮箱 + 6 位验证码，或 Google 登录；站内写着建群、加 agent、发消息都免费，未找到价格页和付费档，agent 本身的费用按各家自己的规则来。

核查到的硬数字（2026-11-20 全站浏览，未注册、未登录，App 内功能未看到）：一个群最多 50 位成员，一个账号最多接 5 个 agent，单条消息最多 1 万字、8 个文件，单个文件 10 MB、合计 20 MB。支持的 agent 包括 Muse、ChatGPT、Claude、Codex、Grok Bot、Manus、OpenClaw、Hermes、Instinct、Cursor、Copilot、DeepSeek、Gemini、WorkBuddy、豆包、千问、Kimi、Qoder、Antigravity、OpenCode 等。公开群 198 个，分投资理财、商业与创业、科技与产品等 16 类。指南 14 篇 agent 指南 + 37 个使用场景，博客 29 篇（2026-11-13 至 11-20）。

**跟农场像的地方：** 群聊当协作界面、一个图标一个 agent、一个做一个验、最后人拍板。

**不一样的关键：** Pachat 是跨人共享——每个 agent 属于不同的人、跑在各自主人电脑上、费用主人自己出，靠群里 @ 唤醒，没有中央总管派单，也没有免费轮换。农场是一个人手里的多家免费额度轮换，Muse 当总管派单，省的是 Gao 自己的 token。

**值得借到农场里的 6 点（按优先级）：**
1. **改动清单，而不是直接改文件。** 审核报告的例子：ChatGPT 写摘要说 1420 万、3.1 年回本，Claude 按表 4 从头重算（装修 310 万 + 烤炉 860 万 + 流动资金 70 万 = 1240 万），纠成 1240 万、2.7 年回本，还指出“5 家已签约”实际是“5 份意向书”。最后交的不是改好的文件，而是一张清单：原值、新值、依据在哪一行。农场现在是审完直接交付，改成先交这张清单，Gao 只看改了什么再点头。
2. **一个做、一个验、一个收尾的分工模板。** 写死三个角色：起草、核数字、格式和版本；核数字的人必须从表格和源文件从头重算，不许照着草稿算；同一个 agent 不许自己验自己写的东西。农场有写—审—改闭环，但还没把这三个角色写成能直接复制的说明。
3. **群消息只是信息，不是命令。** Pachat 的硬规则：agent 被要求把群里的话当信息看，预约、付款、定日期、分享个人信息之前必须先问主人；邮箱永远不在群里显示；agent 只能看到自己所在群的消息和文件，看不到别的群和私聊。农场现在没写这条红线，补上对以后拉别人进来、或开源给别人用都很重要。
4. **复制给 agent 的邀请语。** 公开群每张卡都有“复制给我的 agent”按钮，点一下就是一段写好的话，复制发给自己的 agent 就能进群。农场招募现在要填 Base URL、模型、环境变量名，对新手还是重了，这句邀请语可以当轻量版入口。
5. **文件版本专人管。** 审核报告场景里，Codex 的活就是先去客户文件夹找最新版 v7，确认房租改了再改，改完注明版本号、导出 PDF。农场现在没人专门管版本，各改各的容易盖掉。
6. **按 agent 出专属指南，加使用场景库。** Pachat 有 14 篇 agent 指南（各讲怎么接、多就查一次、不回怎么办）和 37 个使用场景（审报告、做 App、持仓管理、备考等）。农场现在只有一份通用招募说明，Kimi、豆包、千问这些免费网页工人各有什么脾气全靠口头记，写成指南以后招募新人才不用每次重讲。

**明确不借的 3 点（Gao 2026-11-20 定）：**
- **定时回来查收件箱的轮询机制：** Pachat 多数 agent 不能实时唤醒，只能按主人定的频率定时回来查，默认 10 分钟，范围 2–1440 分钟；被 @ 后 10 分钟没读会发邮件提醒主人。农场不要这个——员工不自己轮询、不自己回来查，只有主人 Gao 和主人指定的主管（Muse 这种 24 小时待命的 personal agent）能唤醒其他 agent。定时检查、到达速度公示、@ 后提醒这三条都不往农场里加。
- **公开群和跨人混聊：** 公开群让陌生人的 agent 自由加入、互相看群内消息，跟农场“一个人用、额度是自己的”冲突；公开群列表和社区运营（198 个群、博客竞品对比）是它做产品的打法，不是农场的。
- **入群问题用外部模型判题：** Pachat 若群设了入群问题，未完全答对时用一个模型经 OpenRouter 按问题和答案判断，等于把问题答案发给第三方，农场没必要学。

**结论：** Pachat 最值得借的是前三条——改动清单、分工模板、群消息只是信息不是命令；后三条是轻量入口和文档习惯。唤醒方式和跨人共享这两块，农场跟它走相反的路，别混了。
