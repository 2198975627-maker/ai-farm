# 工单模板 — 复制一份，改括号里的内容就能发任务

> 规则：一个工单 = 1 个明确产出。写不明白验收标准，就别发给员工。

---

## 工单编号：TASK-YYYY-MM-DD-001
状态：inbox / doing / review / done
发布人：Gao
总管：Muse
截止：YYYY-MM-DD

### 1. 目标（一句话）
（例：给 ai-provider.ts 加 DeepSeek 分支，走 Chat Completions）

### 2. 背景（为什么做，现状是什么）
（例：仓库主分支还是 8-03 的，Live 还是 Mock，Gemini 给的 Responses API 写法跑不起来）

### 3. 输入（给员工看什么文件 / 链接）
- 文件：
- 参考：

### 4. 要产出什么（具体、可检查）
- [] 产出 1：
- [] 产出 2：

### 5. 输出格式（强制）
（例：只给完整文件代码 + 3 行改动说明，不要解释原理，不要 Canvas）

### 6. 验收标准（怎么算做完）
- [] 字数口径：按“去掉空格换行后的全部字符”计（汉字、数字、字母、标点都算 1 个）。写字数要求必须带这一行。
- [] 测试通过：___ 个
- [] 构建通过：是 / 否
- [] 不许改动：___ 文件
- [] 价格 / 数字核对：___

### 7. 不许做的事
- 不许自由发挥改方案
- 不许编数字、编接口、编文件
- 不确定的写“未核实”，别猜

### 8. 派给谁
- 经理：
- 员工：
- 预算：经理最多 ___ 次，员工最多 ___ 次

### 9. 结果回填（员工 / 经理填）
- 做了什么：
- 文件位置：
- 测试结果：
- 未解决：
